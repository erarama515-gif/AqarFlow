نفّذ رفع مشروع AqarFlow الموجود في `E:\projects\aqarflow` إلى GitHub الخاص بحسابي، مع ضمان أن المستودع Private وليس Public.

أريد تنفيذ العملية فعليًا، وليس مجرد شرح الخطوات. اتبع المراحل التالية بالترتيب، وتوقف فقط عند وجود خطر حقيقي أو حاجة إلى موافقة لا يمكن استنتاجها بأمان.

### 1. فحص المشروع وحالة Git
- تحقق من المسار الصحيح ووجود ملفات المشروع.
- افحص `git status` و`git branch` و`git remote -v` و`git log` إذا كان Git مهيأ بالفعل.
- إذا لم يكن المستودع مهيأ، افحص الملفات قبل إنشاء `.git`.
- حافظ على كل التعديلات والملفات الموجودة. لا تحذف أي شيء ولا تستبدل تاريخ Git.

### 2. فحص الأمان قبل الرفع
راجع `.gitignore` وتأكد من استبعاد:
- `.env` وملفات الأسرار وملفات إعدادات الإنتاج الحساسة.
- `node_modules` وملفات البناء والكاش.
- نسخ قواعد البيانات المحلية وملفات Backup وملفات Logs التي قد تحتوي على بيانات حساسة.
- مفاتيح SSH والشهادات والرموز السرية وأي ملفات اعتماد.

افحص الملفات المراد رفعها بحثًا عن أسرار فعلية، وليس أسماء الملفات فقط. لا تطبع قيم الأسرار في التقرير أو الطرفية. إذا اكتشفت سرًا أو بيانات شخصية أو قاعدة بيانات حقيقية ضمن الملفات المراد رفعها، امنع رفعها وعالج الاستبعاد دون حذف ملفات العمل الأصلية.

لا ترفع أي ملف حساس لمجرد أنه موجود بالفعل في Git. إذا كانت الأسرار موجودة في تاريخ Git، لا تعتبر حذفها من آخر نسخة كافيًا؛ لا تدفع التاريخ إلى GitHub قبل معالجة الخطر.

### 3. تحديد مستودع GitHub
تحقق من اتصال GitHub باستخدام `gh auth status` إن كان GitHub CLI متاحًا، أو استخدم وسيلة المصادقة الموجودة بالفعل على الجهاز. لا تطلب مني مشاركة Token أو كلمة مرور.

- إذا كان الـ remote الحالي يشير إلى مستودع خاص يخصني، تحقّق من ملكيته وخصوصيته واستخدمه بعد فحص الأمان.
- إذا لم يوجد remote مناسب، أنشئ مستودعًا جديدًا باسم `AqarFlow` واجعل `--private` محددًا صراحةً.
- إذا كان الاسم مستخدمًا بالفعل أو كان الـ remote الحالي عامًا أو تابعًا لشخص آخر، لا ترفع إليه ولا تغيّر خصوصيته أو تستبدل الـ remote دون فحص. اختر اسمًا مناسبًا لمستودع خاص جديد إن أمكن دون التأثير على المستودع القديم.
- لا تنشئ مستودعًا عامًا تحت أي ظرف.

### 4. تنفيذ الرفع
- احتفظ بالفرع الحالي والتاريخ الموجود.
- أضف فقط الملفات المناسبة بعد مراجعتها.
- أنشئ commit جديدًا إذا لزم الأمر، برسالة واضحة.
- ارفع الفرع المطلوب إلى المستودع الخاص.
- لا تستخدم `git push --force` أو `git reset --hard` أو أوامر حذف جماعي.
- لا تنفذ Deploy ولا تغييرات على قاعدة البيانات.

إذا فشلت المصادقة أو ظهرت مشكلة صلاحيات، اشرح السبب بدقة ولا تحاول تجاوز الحماية.

### 5. التحقق النهائي
بعد الرفع، تحقق فعليًا من:
- عنوان مستودع GitHub.
- أن `isPrivate` يساوي `true` من بيانات GitHub الفعلية، وليس مجرد افتراض.
- أن الفرع المرفوع يطابق الـ commit المحلي المقصود.
- أن الملفات الحساسة غير موجودة في الملفات المرفوعة.
- أن التعديلات المحلية الأصلية لم تُفقد.

أعطني تقريرًا مختصرًا يتضمن رابط المستودع، اسمه، حالة الخصوصية، الفرع والـ commit المرفوع، وأي ملفات مستبعدة أو خطوات تعذّر إكمالها.

ابدأ بالفحص ثم نفّذ بأمان. لا تعتبر العملية ناجحة قبل التأكد من أن المستودع Private وأن الرفع اكتمل بالفعل.
